# Frontend workflow

1. 从用户动作开始画出页面、路由、状态、请求和响应的关系。
2. 把接口类型、表单校验、错误提示和重复提交保护放在明确的边界上。
3. 列表场景验证分页、筛选重置、排序、空结果、加载失败和并发响应顺序。
4. 弹窗或抽屉关闭后清理临时状态；编辑成功后刷新或局部更新的策略保持一致。
5. 用组件测试覆盖关键交互，再运行仓库声明的类型检查、单测和构建命令。

## 常用细则

- 优先使用组件框架的表单、表格、弹窗、日期和级联组件；校验规则与提交按钮状态保持同源。
- 复杂跨页事实才进入全局 store；组件临时状态和可复用异步逻辑优先使用 composable。
- 路由按需加载，模板避免混合条件和循环；事件、props 和 emits 要有清晰类型边界。
- 异步请求在 `finally` 恢复 loading，错误提示面向用户；大列表考虑分页、虚拟化、防抖和取消过期请求。
- 审查时额外检查无障碍、焦点顺序、键盘操作、响应式布局和资源释放。
