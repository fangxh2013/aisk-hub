# Database workflow

1. 记录实体、访问路径、唯一性、删除策略、容量和兼容要求。
2. 让索引服务于真实过滤、排序和关联，检查最左匹配与选择性。
3. 迁移脚本使用明确版本、幂等边界和失败处理，避免无条件破坏性操作。
4. 结构对齐按环境分别读取，差异报告包含来源、目标和风险，不猜测缺失对象。
5. 在测试数据上验证执行时间、锁影响、回滚/补偿和旧版本兼容。

## 设计与变更细则

- 类型按范围、精度、排序、时区和 NULL 语义选择；文本、二进制、JSON 和时间字段分别评估容量与查询需求。
- 主键、唯一约束、外键或应用级一致性要说明取舍；索引避免重复、低选择性和无边界的宽扫描。
- 查询使用参数化条件，分页有稳定排序；深分页或大批量处理评估游标、分批和限流。
- 结构快照保留环境、时间、来源和版本，差异生成与执行分离；破坏性操作需要人工确认和恢复演练。
- 敏感列最小化读取并在日志、导出和分析结果中脱敏，生产查询默认只读且限制行数。
