# Operations workflow

1. 建立环境、区域、服务、实例和时间窗清单。
2. 先看健康状态、事件和最近发布，再按时间线关联日志与指标。
3. 比对期望配置、实际加载配置、镜像版本和启动参数，记录来源。
4. 对失败分成代码、配置、依赖、资源和权限五类，避免“重启试试”掩盖根因。
5. 交付只读证据、风险和回滚/人工操作建议；不把未执行的动作写成已完成。

## 按问题类型路由

- 容器问题先看事件、退出码、探针、资源和挂载，再看应用日志；输出修订后的配置候选，不直接改集群。
- 镜像问题核对构建上下文、分层、基础镜像、运行用户、健康检查和漏洞扫描结果。
- CI 问题按源码、依赖、构建阶段、制品、凭据引用和部署触发链逐段定位。
- 配置问题区分声明值、渲染值和进程实际值，敏感值只验证键存在和格式，不打印内容。
- 需要写入时停止在计划和影响评估，交由具备权限的操作者执行并记录结果。
