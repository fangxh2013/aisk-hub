# Service workflow

1. 记录接口的请求、响应、错误码、鉴权要求和兼容策略。
2. 将校验、业务决策、外部调用和数据写入放在可测试的边界内。
3. 对分页、排序、过滤和批量操作设置上限，并验证空输入与重复数据。
4. 事务只覆盖必要的本地写入；跨服务一致性采用明确的补偿或重试策略。
5. 为每个修改点选择最小测试集，并保存失败响应、日志和构建结果作为证据。

## 分层与契约

- Controller 负责协议、输入校验和响应映射；Service 负责业务决策与事务；Repository/Mapper 只负责数据访问。
- DTO/VO 与持久化实体分离，统一错误结构不要泄漏堆栈、SQL 或内部字段。
- 外部客户端声明超时、重试、熔断、幂等和 fallback；不要对非幂等写请求盲目重试。
- 分页默认稳定排序并限制页大小；批量接口报告成功、失败和跳过项，不吞掉部分失败。
- 单测隔离时间、随机数、网络和数据库；集成测试使用临时依赖或容器，不连接真实环境写数据。
