# Release checklist

1. 固定比较基线、目标分支、提交范围和工作区状态。
2. 汇总应用代码、依赖、数据迁移、配置、密钥引用和构建产物变化。
3. 标记受影响服务、执行顺序、前置条件、兼容窗口和回滚路径。
4. 为每一项指定验证命令、观察指标或人工确认点。
5. 输出已证实、未证实和明确不受影响三类结果。

## 差异分类

- DDL/迁移：版本、执行顺序、幂等性、锁风险、回滚或补偿；不要把脚本存在当作已执行。
- 配置：DataId/键名、格式校验、默认值、敏感引用和生效方式；不复制秘密或内部地址到报告。
- 构建：受影响模块、依赖缓存、镜像/制品标签、流水线阶段和触发条件。
- 服务：接口兼容、数据读写、上下游顺序、灰度观察和停止条件。
- 报告：每项都带来源、负责人角色、验证信号和人工确认点；分析阶段不执行发布写操作。
