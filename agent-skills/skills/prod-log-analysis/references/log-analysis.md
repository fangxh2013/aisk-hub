# Log analysis

1. 统一时间、服务、版本和请求上下文，先确认数据是否完整。
2. 按错误类型、堆栈指纹、状态码和关键字段聚类并统计趋势。
3. 查找首次出现点，和部署、配置、依赖变更做时间关联。
4. 选择最小只读查询验证候选根因，并保存查询条件与脱敏结果。
5. 报告影响范围、置信度、尚未排除的假设和安全的修复验证方案。

## 重点模式

- 把 UTC/本地时区、索引分片和采样缺失写进数据质量检查，避免错过真实窗口。
- 错误指纹之外保留请求 ID、版本、实例和首次/最近时间，便于和发布时间线交叉验证。
- “缺字段/缺表”类错误要分别核对代码查询、目标结构、迁移版本和实际加载版本，不能直接断言迁移漏跑。
- 需要定位责任时只使用受授权的版本历史和行级证据；责任归因与根因确认分开报告。
- 结果分为事实、候选根因、已排除项和下一条只读验证，避免把相关性写成因果性。
