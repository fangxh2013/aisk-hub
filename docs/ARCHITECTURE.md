# aisk-hub 核心架构设计

本文档定义 `aisk-hub` 公共开源内核的架构分层、协同边界、私有插槽规范与双轨验收模型。

---

## 一、三层架构划分 (Core / Adapter / Runtime)

```text
┌─────────────────────────────────────────────────────────────┐
│                       AI 客户端生态层                       │
│    Codex (GPT-6) │ Claude (Opus 5) │ Antigravity │ WorkBuddy│
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                    Adapter 适配层 (协议接入)                 │
│   · 进程/会话识别 (detect_tool)   · 项目级生命周期钩子 (Hooks)  │
│   · 原生系统弹窗 (AppleScript)   · Stdio MCP 2.0 服务端     │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                    Core 内核层 (通用工程闭环)                │
│   · 9 大规范领域技能 (短入口 + References 按需加载)           │
│   · 逻辑别名路由器 (SkillRouter) 平滑映射 26 旧技能          │
│   · SQLite WAL + CAS + Outbox 任务状态机 (Fencing Token)    │
│   · 离线安全四态契约 (Fail-Fast 快速探针 + 敏感脱敏)        │
│   · Token 效率行级审计与质量门禁                             │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                  Runtime & Overlay (私有业务层)             │
│   · aisk-private 声明式受控插槽 (Slot Overlay v2)           │
│   · 项目 Profiles (环境拓扑/只读凭据引用/数据源)            │
│   · 运行时隔离工作区 (~/.aisk-runtime/hub/tasks)            │
└─────────────────────────────────────────────────────────────┘
```

### 1. Core (公共通用内核)
内核负责标准任务状态机、工作区隔离、领域技能定义、路由分发、高危操作审计与门禁校验。公共内核不硬编码任何具体企业/项目的专有业务规则、内部系统地址、凭据或私有知识。

### 2. Adapter (多客户端适配器)
针对不同 AI 工具的运行差异（Codex、Claude、Antigravity、WorkBuddy、WorkBuddy AI）提供专门适配：
- 负责环境变量识别与会话唯一标识提取；
- 负责挂载各端特定的生命周期钩子；
- 负责统一调用系统原生 `/usr/bin/osascript` 弹窗，并遵循 `动作-工具｜任务号` 标题协议；
- 负责各端特有的技能与 MCP 配置文件分发。

### 3. Runtime & Overlay (私有运行时与插槽覆盖)
- **私有仓 (`aisk-private`)**：不复制公共技能，通过 `OVERLAY_MANIFEST.yaml` (v2) 声明式注入业务私有插槽（如微服务包名前缀、菜单图标前缀、环境拓扑）；
- **任务运行时**：状态机与工作区落盘于 `~/.aisk-runtime/hub/tasks`，与代码仓物理隔离。

## 二、双轨验收模型 (Dual-Track Evaluation Model)

为彻底破除“离线单测跑通即自嗨宣称交付”的伪完成漏洞，系统设立严格的双轨制验收：

### 1. 离线契约分 (Offline Contract Score)
通过自动化程序（`tools/verify_spec.py`）严格验证静态契约：
- **Schema 校验**：所有事件、Overlay、MCP 响应 JSON Schema 语法与约束闭环；
- **协同状态沙箱**：SQLite WAL、CAS 冲突检测、Stale Fencing Token 拦截、事务 Outbox 双写；
- **离线 MCP 安全**：不可达时返回 `offline_unavailable`，强行拦截伪造 SQL 响应；
- **全历史隐私扫描**：通过 `git rev-list --all` 穿透扫描全量 Git 历史；
- **Token 预算审计**：静态检查常驻技能体量、上下文预算与重复行比例。

### 2. 真实运行分 (Real Runtime Score)
必须由真实操作系统的执行证据链支持：
- **客户端真实发现**：四大客户端能真实索引并加载技能；
- **真实分发链路**：通过 `aisk link` 真实分发，旧命令（如 `dev-code`）经由 `SkillRouter` 真实加载 `backend-engineering/SKILL.md`；
- **真实弹窗可见性**：高危写操作弹出的系统原生对话框中，标题清晰可见对应工具名；
- **私有 Slot 真实注入**：私有业务参数通过 Overlay 解析器正确编译入运行时，无未声明字段；
- **零外部历史依赖**：运行时完全自包含，不依赖任何已废弃的软链接或外部仓库。

> [!IMPORTANT]
> **一票否决规则**：任一 P0 级真实运行门禁失败，综合评分封顶 **89.0 分**，严禁宣称 99.9+ 认证。

## 三、12 步平滑重构安全流水线 (Change-Safety Pipeline)

为防止大重构扯碎业务开发，系统演进严格执行 12 步流水线：

1. **盘点边界**：全面审计 26 个技能中的通用工程能力与专有业务特征；
2. **抽取通用**：提炼纯净的领域工程规范，放入公共内核；
3. **隔离专有**：将企业专有规则迁移至私有仓 `rules/` 与 `profiles/`；
4. **建立短入口**：创建 9 大规范技能的 `SKILL.md`（6 要素短入口）与 `references/`；
5. **别名路由器**：在内核中完善 26 旧名称到 9 规范技能的逻辑别名映射（零 symlink）；
6. **接入 CLI**：将 `SkillRouter` 接入 `aisk link` 与 `aisk skill` 真实分发命令；
7. **升级 Overlay v2**：私有仓升级为声明式受控插槽，并生成防篡改 Lock 锁文件；
8. **清理私有冗余**：删除私有仓中与公共仓重复的 26 个技能物理目录；
9. **双仓测试回归**：运行公共仓与私有仓全量自动化单元测试与契约门禁；
10. **客户端真实 dry-run**：在四大客户端实测真实加载与命令路由；
11. **文档与体验完善**：完备安装、升级、回滚与审计说明；
12. **物理下线**：最后一步生成迁移清单与备份，安全下线旧物理目录。
