# Token 效率与低碳运行

aisk 将 Token 效率作为正确性、安全性之外的工程门禁。目标不是盲目截断上下文，而是让每次 AI 任务只接收完成当前步骤所需的最小事实集合。

## 设计约束

- 常驻规则只保留身份、权限、隐私、高危动作和验收约束。
- 旧技能通过逻辑别名路由，不把旧技能正文全部拼入上下文。
- 业务事实按需从 MCP 或本地快照读取，不硬编码进技能正文。
- 交接只传目标、差异、验证结果、哈希和事件 ID；完整日志留在本地审计存储。
- Token 预算只能阻断无效膨胀，不能删除安全、隐私和验证门禁。

## 离线检查

```text
./bin/aisk contract tokens
PYTHONPATH=agent-skills python3 tools/verify_spec.py --no-report-files
```

检查使用确定性的字符估算，不冒充任何模型的真实 tokenizer；接入具体客户端后，可将真实 Token 用量作为额外遥测，但不得降低离线门禁。

Token 减少通常有助于降低计算量和能耗，但实际碳排还取决于模型、硬件、缓存、区域电力结构和调用次数，因此这里把“少重复上下文、少无效输出、可复用缓存”作为可验证代理指标。

契约报告中的 token 分数属于确定性离线估算；它不代表任何一个真实客户端的 tokenizer、上下文
缓存或调用成本。客户端联调完成前，效率门禁和安全/隐私/验证门禁都必须保留，不能用删除规则
或把 26 个 alias 展开进提示词来换取表面缩短。
